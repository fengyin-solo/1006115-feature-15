# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 浆液拌制配料偏差核对

针对「配方算一遍、领料单算一遍，两个数对不上；水灰比/稠度补录又和配方对不上」的问题，
浆液拌制增加了按批次编号的配料偏差核对：

- **三处取数收成一份**（`src/data/mortar-domain.ts`）：
  - 配方用量取**配方库**，按拌制日期适用当时生效的配方版本（版本化，只增不改）；
  - 实际水泥、膨润土用量以**领料单**为准（拌制批次行的「领料单号」可溯源）；
  - 水灰比、稠度以**现场记录本实测值**为准。现场记录与领料单打架时，数量听领料单、拌制指标听现场记录。
- **判定线（V1，2026-01-01 起施行）**：水泥用量偏差 ±5%、膨润土用量偏差 ±5%、水灰比偏差 ±0.05、
  稠度偏差 ±20mm。任一条超线即不合格，结论里逐条写明「差在哪个料、配方多少、实际多少、允许多少」。
  水泥或膨润土超线的批次在「提交检验」处直接拦截；试验检测侧关联该批次的委托也不许「送样委托」。
- **标准/配方调整**：只有顶栏切到「拌制站负责人」才能改，改动产生新生效版本并自动对已拌制批次
  全量重核；早于新生效日拌制的批次仍选当时版本、结论不变（早先判定留在核对记录的 `history` 里）。
- **同一批次重复提交核对只留最早一条**：再递一遍返回首次结论，不新增记录；数据不齐（缺领料数量或
  现场指标）整单不写，不留半条。
- **存量批次**：首次读取时按拌制日期自动补登核对一遍，标记「按拌制日期补登」。
- **结论两处同源**：核对记录只存一份（localStorage 键 `shield-tunnel-construction:mortar-checks`），
  试验检测的委托清单与同步注浆的待用浆液批次清单都通过 `listDeviationBatches()` 读同一份偏差批次，
  两处入口条数必然一致；批次行里的配方列、偏差列、结论列均在读时带出，不另写第二份明细。
- 配方、标准、核对结论另有独立存储键（`mortar-recipes`、`mortar-standards`、`mortar-checks`）；
  重置浆液拌制模块时三者一起回到初始，避免留下对不上的半套数据。
